# 读图检查清单（F3③ · 随包正本）

> **这是读图项，不是闸门项。** 本清单的每一条都**只读图可判**：结构化回读里**没有**它的对象
> （语义 / 渲染结果 / 交互意图），写脚本查不出来（E1 的原理性边界）。
> **不得把它们混进 `layout-audit` 之类的机械闸门冒充机器判定**（§1.4 纪律 / H3 零目测评分）——
> 它们的产出是**带可回放证据的观察记录**，不是分数。
>
> **为什么必须是必选项**（F3①，2026-09-18 起）：运行 B 的五维 8.5 分 PASS 里躺着 168 格无轴标的热力图
> （`lessons.md` #68 同族：像素一致不能证明结构正确）——读图不做，这一环就**结构性没人看**。
> 措辞矛盾已于 `visual-critic.md` §1.6 消除：**读图不是「可选附加」，是「有图环境的必选项」**；
> 无读图能力的环境仍按 §1.6 通用档出分 + `unassessed` 如实列缺（两句话同时成立，方向相反的滥用各挡一个）。

## 一、怎么用（执行协议）

1. **谁执行**：`_evidence.mode = structured+vision` 的评审（有读图能力 + 已导出 PNG）。
   `structured-only` 的评审**不适用**本清单——如实跳过，不得伪造记录。
2. **逐条留痕**：每条给出 **verdict ∈ `ok` / `issue` / `n-a`**：
   - `ok` —— 查了，没发现问题（**空口 ok 不算留痕**，须能指出「看了哪张图的哪个区域」）；
   - `issue` —— 发现问题，**必须**写「看到了什么 + 对应节点或区域（nodeId 优先）+ 影响哪一维」
     （与 `visual-critic.md` §1.6 增益档观察同一条可回放纪律）；
   - `n-a` —— 本产物不存在该检查对象（如无图表则 R1–R4 不适用），**必须带一句理由**。
3. **记录落盘**：run 目录一份 `read-image-review.json`（格式见 §三），与 critic report 同级归档。
   **落进报告字段不必手抄** —— `tools/read-image-merge.mjs` 把记录自动落进
   critic report 的 `_evidence.visionObservations` / `unassessed`（幂等、带内容指纹留痕，1.3·A3）。
4. **与闸门的分工**：本清单**本身**靠执行纪律；记录的**存在性与完备性**（每条都有 verdict、
   issue 带证据、n-a 带理由、与报告档位一致、n-a ⊆ unassessed、ok-issue ⊆ visionObservations）
   由 `qa-critic.mjs` **QA9**（`--review <read-image-review.json>`，1.3·A3 接线）做机械裁判；
   structured+vision 却**不提供** `--review` → 记 WARN（未核对不得折算为通过）。

## 三、留痕记录格式（`read-image-review.json`）

```json
{
  "checklist": "read-image-checklist",
  "checklistVersion": "1.0.0",
  "mode": "structured+vision",
  "images": ["l4-shot-p1.png"],
  "items": [
    { "id": "R1", "verdict": "issue", "evidence": "热力图区域（节点 7:328）168 格无轴标，读者无法知道色深对应什么量", "dimension": "Commercial" },
    { "id": "R2", "verdict": "ok", "evidence": "逐面板核对 KPI 卡与图例，数值均带单位" },
    { "id": "R11", "verdict": "issue", "evidence": "并置证据：anchor-compare 报告（快照 sha256=4c7264d8…）画布主色 #00d4ff 距锚点色板最近 129.8、均距 65.5，色彩重合度低；观感对照：KPI 卡强调色面积远大于 linear-app 同场景的单点 accent", "dimension": "Commercial" }
  ]
}
```

**格式约束**（F3 第 2 步的机械裁判按此校验）：`items` 必须**覆盖清单全部 id**；
`issue` 必带 `evidence`（含节点或区域 + 影响维度）；`n-a` 必带 `note`；`ok` 必带非空 `evidence`（看了哪）。
**缺一条 = 没查 = 按 `visual-critic.md` §1.6 记 `unassessed`，不得出完整分。**

## 四、边界（如实记）

- 本清单**不产生分数**：它产出的 issue 走 critic report 的常规 issue 通道（带证据、影响维度），
  由既有五维评分模型吸收；`ok` / `n-a` 只证明「查过」，不证明「没问题」——**查过没问题 ≠ 评过分**
  （代理指标纪律：记录存在性是覆盖的**代理**，观察质量靠可回放证据保真）。
- R11 曾是**显式的空环**（立项书 §4 判据 1 要消掉的那项）—— **2026-09-18 已消**：F3② 装置
  （`tools/anchor-compare.mjs` + `references/anchor-compare.md`）产出可回放的并置证据，
  本条与并置协议**合流**：机械证据（色 / 字 / 字阶差值）由装置给，观感对照按本格式留痕。
- 清单条目**可增不可删**：发现新的「只读图可判」缺陷模式时，新增 id 并在来源列注明出处
  （F4 后续来源过筛的读图内核继续从这条通道进来，`design-criteria-intake.md` §4.5）。
