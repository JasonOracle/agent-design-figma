## 1. 架构与协议

1. **Figma 插件的网络边界**：网络能力只在插件 UI iframe；主线程（Plugin API realm）没有网络权限。唯一可行架构 = UI iframe 长轮询 + `postMessage` 转发主线程执行。⚙️（`bridge/server.js` + `figma-plugin/ui.html`）
2. **长连接 + 内存队列的服务，投递前必须校验对端存活**。插件重跑/重连后旧 long-poll socket 已死，不检查就会**静默吞命令**（调用方永远等到 `NO_RESULT`）。配套要有「谁吞了消息」的告警，否则极难归因。
3. **超时 ≠ 未执行 ≠ 可重试**。CLI 超时只是「信息缺失」，那批 op 可能已在插件侧执行完。曾带 `TRANSIENT` 正则盲目重试，把同一块画板复制了 3 份。重试只允许在**确认零副作用**的连接层错误上进行；大 batch 按实测放大超时。⚙️（`failedAt.step` 断点续跑，见 `bridge-ops.md`）
4. **对客户端做注册制 + 握手门**：带轮询循环的页面一旦脱离宿主环境（如被丢进 IDE 预览面板）会变成「假客户端」截胡命令，且假阳性报 `connected: true`。要求先 hello 注册再 poll（403 拦截），页面未收到宿主握手则永久惰性。
5. **增量扩展的最小改动面**：Bridge 对 op 无白名单、直接透传，校验全在插件侧 → 新增 op 只改 `figma-plugin/code.js`，Bridge 与 `ui.html` 一行不动。⚙️（`tools/qa-plugin.mjs` 断言 op 数）

## 2. Figma Plugin API

6. **manifest 的 `networkAccess.allowedDomains` 不支持 `127.0.0.1`**（文档只例举 `localhost`，实际就是不支持）。Bridge 因此额外绑 `::1`，让 Windows 上 `localhost`（可能解析到 IPv6）也能通。
7. **`documentAccess: dynamic-page` 下同步 `figma.getNodeById` 被禁用**，必须 `getNodeByIdAsync`。且**改完插件代码必须重新运行插件**（已加载的代码不热更新）。
8. **部分写入会留孤儿节点**：`create-rect` 先建后解析 `parentId`，失败时矩形已挂在页面根部。「命令报错」**≠**「什么都没写」→ 报错后必须回读画布确认残留再清理。
9. **`node.duplicate()` 不存在，是 `clone()`**。`remove` / `resize` / `appendChild` 都是正常名字，唯独复制换了名——凭印象写必错。定位手法：临时加诊断 op，输出原型链属性名。
10. **自动布局容器的子节点不能直接写 x/y 或尺寸**；要动就针对容器本身，或先 `set-auto-layout --mode none`。
11. **实例无法插入/替换子节点**（无 component-swap / variants）。可组件化的走「实例 + 延迟覆写」（`ovr` + `applyOverrides`）；不可组件化的**如实使用原生 frame，不要用 mock 掩盖缺口**。
12. **实例名默认继承组件名**，语义重命名要显式批量做（`set-name`）。
13. **`get-node` 的 `depth` 只在 `detail: true` 时递归**，`detail:false` 返回浅层假象（曾报 4 节点、实际 274）。审计/读回一律 `detail:true`。⚙️（1.1 已修：`depth` 与 `detail` 独立生效，见 `bridge-ops.md` §2.3；`layout-audit.mjs` 会提示深审不可用）
14. **mock 测试永远测不出真实 Plugin API 约束**（`dynamic-page` 禁同步 API 就是 mock 环境永远发现不了的）。mock 通过 **≠** 真实成功，必须保留「真实画布断言」层。📏

## 3. 设计与数据流

15. **「文档里的画布内容」必须从读回的 tree 文件取值，禁止凭记忆写**。曾凭印象编造 KPI 标签与科目数量，被逐字核对揪出。
16. **审计的预期值也要对齐真实设计意图**（例：某按钮宽 380 是 `FILL` 全列宽的结果，而非固定 348）——拿错基线会把正确实现判成违规。
17. **像素回归能暴露源设计本身的几何错误**：饼图扇区变形、折线曲线不经过数据点（vector 仅 76px 高）、网格线左移 52px 与柱不对齐。这类必须归类为**源设计差异**并如实上报，**不能偷偷在实现层「修正」**。

## 4. 测试策略

18. **两层测试职责分开**：`selftest`（mock + CLI `--dry` 断言，不需要 Figma，快）+ **真实画布断言**（强制插件在线、逐项回读确认落地）。`--dry` 是验证「CLI 参数 → op 映射」的利器，比端到端报错快一个数量级。⚙️（`tools/qa-*.mjs`）
19. **测试编排里端口 / token 这类环境参数必须同时喂给被测双方**（曾因 selftest 与 CLI 用了不同 token，全部 401 秒失败）。⚙️（`qa-bridge.mjs`）
20. **反向用例与回归守卫是必须的**：坏 token → 401、无插件 → `PLUGIN_OFFLINE`、死 waiter → `NOT_PICKED_UP`（**不许** `NO_RESULT`）。且示例文件一改，selftest 不能跟着烂——steps 从文件读，不硬编码。⚙️（`qa-bridge.mjs` 13 项）

## 5. 工具与环境坑（Windows）

21. **同一条消息里对同一个文件发起多条编辑会静默丢一条**，而工具仍报成功。同文件编辑必须**串行**；跨文件改完要用检索核验关键标记是否都落地。📏 **对 Agent 尤其致命——它不会收到任何报错。**
22. **npm install 在没有 package.json 的目录里，会向上爬到最近的一个**（在空子目录里装依赖，会误装进上层项目）。本 Skill 的答案是**零依赖**，天生不触发此坑。⚙️
23. **浏览器自动化会话在多次命令调用之间不保活**：`open → resize → screenshot → eval → close` 必须串在**一条** shell 命令里。
24. **系统代理会劫持 localhost 的 curl（502）**：必须 `--noproxy '*'`。
25. **Git Bash 里 `taskkill //F //PID` 有转义问题** → 改用 PowerShell `Stop-Process -Id <pid> -Force`。
26. **后台 dev server / Bridge 会随会话意外退出**：重启命令要写进文档（本仓库：`node bridge/server.js`，零参数）。插件在 Bridge 停机期间会 backoff 重试，**Bridge 一起来 0.1s 内自动重连**，不需要重跑插件。
27. **外部工具导出的图片会落在工具自己的目录**，使用前要拷回项目目录再引用——否则交付物里出现一个本地存在、别人拿不到的路径。
28. **环境变量大小写重复会搞崩 .NET 安装器**（`http_proxy` / `HTTP_PROXY` 成对存在时，VS Build Tools 安装器秒退 5008）。

## 6. 协作模式

29. **每阶段完成后暂停等验收，不删旧产物**——保留旧产物形成**可追溯的阶段地层**，翻车时能回退对照。
30. **无法继续时明确说出缺什么**：需要 fileKey 就直接要链接，**不要猜**，也不要假装跑过。

## 7. 本仓库新增（1.1–1.2）

31. **安装副本会与开发仓库漂移**：曾出现「安装副本停在旧版本 + 带未提交补丁，说不清哪个是正式版」。**对策**：`VERSION` + `CHANGELOG.md`，且探针输出必须带 `version`，让每份交付物都能回答「由哪个版本产出」。⚙️（`runtime-check.mjs`，见 A3）
32. **校验器的判断顺序本身就是缺陷来源**：`qa-l2` 原先**先判色板命中、再判 derived**，于是「把派生 Token 填成任意一个色板色」能蒙混过关（写 `#000000` / `#FFFFFF` / primary 本身都不被发现）。**对策**：带 `derived:` 前缀即**强制公式复算**，不看色板。⚙️（`tools/qa-l2.mjs`）
33. **校验器必须有配套的变异测试，否则它的「全绿」没有意义**：逐项注入已知错误，确认能抓出来。上条漏洞就是这么抓出的。⚙️（`tools/qa-l2-mutation.mjs`，16 例）
34. **文档与实现脱节，靠人工勾选治不好**：上游把「检查文档引用」列为发布前人工勾选项，**勾了但没做干净**——1.0.0 文档里仍留着「Python QA 脚本（90+ 断言）」等 12 处失效引用，Agent 真的会去找。**对策**：`tools/check-refs.mjs` 机器闸门 + 非零退出。⚙️（A4）
35. **打包排除项会悄悄删掉质量资产**：上游有 845 条断言的现成 QA 设计与实现，被发布包排除，**用户一条都拿不到**；同时 L5 Export Gate 变成空规则。**对策**：C3 把 QA 体系 Node 化收回包内，不做就是自欺。⚙️（C3，进行中）
36. **筛选条件要正向描述形状，别用反向排除**：`qa-l2` 原按「`example-` 开头 且 **不是** `.dsspec.json`」挑 Brief，一旦目录里出现**新的兄弟类型**（如 `example-health.ops.json` 这种 L3 构建计划样例），它就把非 Brief 当 Brief，报出「同名 Spec 缺失」这种莫名其妙的失败。改成 `^example-[^.]+\.json$` 的正向形状即免疫。**判据：靠「排除已知的坏东西」写的规则，会在出现未知的新东西时失效；靠「只接受已知的好形状」写的规则不会。** ⚙️（`qa-l2.mjs`，1.2 加 precheck 样例时踩到）
37. **凡是「算得出来的数字」，手写过一遍就必须有一次复算**：DS Spec 的 `accessibility.contrast` 要求逐条给出对比度结论，13 条声称值里 **9 条**与 WCAG 公式不符（偏差 0.17~1.64，方向还不一致——不是同一个错误公式，是根本没算）。更糟的是其中一条错值还被抄进了 `design-system-spec.json` 的字段描述，**成了下游的「参考事实」**。手写数字的危险不在它错，而在它**长得对**：`16.1:1` 和 `17.7:1` 在散文里无法分辨，只有公式能分辨。**判据：可计算的量一律配复算工具，且复算要覆盖「已写下的历史数字」而不只是「新产出的值」。** ⚙️（`contrast-audit.mjs`，1.2 C1 上线即抓到）
38. **判定阈值时不许先舍入**：WCAG 明确「比值不得先舍入再判定」。`#777777` 对白底是 `4.478:1`，显示成两位小数是 `4.48`、显示成一位是 `4.5`——按一位小数看它「达标」，按原值看它**不达标**。工具里 `toFixed` 只能用于**显示**，判定必须用原值，并在贴阈值时打 `⚠边界` 标记。**判据：任何 `round(x) >= limit` 的写法都要问一句「x 本身达标吗」。** ⚙️（`contrast-audit.mjs`，配变异测试「边界灰」用例守住）
39. **测「对端会认为某端已掉线」时，不能用短 sleep 假装**：B2 的「插件掉线」用例原本是「停掉 mock 轮询 → 睡 300ms → 断言核对失败」。但 Bridge 判定插件在线用的是 **45s** 的 stale 窗口，而 mock 的在途长轮询最长 500ms——300ms 之后它仍可能把停摆前的最后一条命令答掉，于是这条用例**在赌时序**，实测会偶发假绿（同一份代码连跑两次一绿一红）。修法是把「不应答」变成确定性事实（停摆后**连在途命令也不回**），而不是加长 sleep。**判据：凡是靠「等一会儿它就该失效了」写的断言，先去读对端判定失效的窗口是多少。** ⚙️（`precheck-mutation.mjs`，1.2 C3 期间发现）
40. **「有没有实测痕迹」这类判定要判形状，别用关键词袋**：`qa-critic` 移植上游时照搬了它的关键词袋 `["px","#",":","%","档","级","分",…]`，其中「级」「分」会命中「不够**高级**」「大部**分**」——于是「整体观感不够高级」这种**纯观感话术**照样通过，而它正是 `critic-report.json` 明令禁止的（`suggestion` 不得写「不够高级」）。**判据：关键词袋里的字越短越危险（「级」「分」「档」都会被近义词命中）；能判形状就判形状（`\d+px` / `#RRGGBB` / 带单位的量），并且必须配一条反例用例钉住它。** ⚙️（`qa-critic.mjs`，变异测试「evidence 无实测痕迹」用例守住）
41. **JSON Schema 的 `if/then` 只能叠加约束，「放宽」必须写在 `else`**：`export-manifest.json` 原把 `exports.png.minItems: 1` 写在基座，再在 `then` 里给 design-phase `minItems: 0`——`allOf` 是**合取**，`then` 撤不掉基座的约束，净效果仍是 `minItems: 1`。于是 Schema 的 `description` 写着「design-phase 允许 exports.png 为空」，**语义上根本不允许**：随包的 `example-highway-export.json` 一直是 invalid，只是从没人真校验过（ajv 独立复核证实）。同理 `$ref` 的兄弟键在 draft-07 里**应被忽略**、在 ajv 里却生效，也别依赖——要叠加约束就用 `allOf` 写明白。**判据：Schema 里每一句「允许…」「…必须…」都要有一条能证伪它的实例；写不出反例的约束等于没写。** ⚙️（`qa-export.mjs` QA1，正反两例内置自检）
42. **可追溯性的判据是「路径能解析」，不是「前缀看着对」**：token 映射的 `source` 写 `preset:enterprise-dashboard.visualSystem.typeScale`——五类前缀合法、看着很像，但四套 Style Preset 里**都没有 `typeScale` 这个键**（真名是 `typography`），17 条溯源全是假的。前缀校验只能证明「格式对」，证明不了「指的东西存在」。**判据：凡是 `命名空间:路径` 形式的溯源字段，都要真去那个命名空间里把路径解析一次。** ⚙️（`qa-export.mjs` QA9）
43. **「快照 / 副本 / 汇总」类字段必须与事实源逐一复算**：`export-manifest.json` 的 `tokens[].value` 是**导出给前端的最终值**、`source` 是溯源、`project` 是产品名，三者本该从 DS Spec / Brief 抄来，却从没人核对过——实测 **32 处**对不上：`health` 的品牌色写 `#5A5CF0`（Spec 是 `#0FB5AE`）、圆角写 8/12/16（Spec 是 6/8/10）、`project` 多了个「 App」后缀；`highway` 的警告色写 `#F5C542`（Spec 是 `#FFB547`）、字阶 value 直接写成自由文本「14（TY-3 大屏提升档）」。**与 #37 是同一类病：抄来的值长得对，只有复算能分辨。** 判据：一份产物里凡是从别处抄来的字段，都要能**沿它自己声明的关系追回源头、逐字相等**。⚙️（`qa-export.mjs` QA5/QA8）
44. **同一个名字不能装两个不同的东西**：`example-health` 这个名字下同时住着两个项目——核心示例 `example-health.json` / `.dsspec.json` 是「AI 型衣 / 美业」（品牌紫 `#5A5CF0`、字阶 24/17/15/13/15、圆角 8/12/16），而随包副本（当时文件名前缀为 health-design-）是「AI 智能健康管理 / 医疗」（青绿 `#0FB5AE`、字阶 26/16/14/13/16、圆角 6/8/10）。两边**各自内部自洽**，所以任何只查单份文件的校验器都不会报警——**只有把同前缀下的产物放在一起比才会暴露**。**判据：发现同名前缀下住着两个项目时，先显式记下来交给人决策，不要各按各的修——那只是把分裂固化。** ✅（**1.2 收尾已闭环**：经用户裁决采用**最窄的一种**——只给**导出包随包副本改名**：清单改为 `assets/examples/export/example-healthcare-export.json`，随包 brief / spec / build-log 三个文件的前缀 health-design- 与 health-build- 一并改为 healthcare-（含清单内 5 处 `source.*` 与 `files[].*` 交叉引用、spec 的 `_source` 叙述），**核心示例 `example-health.*` 保持不动**——它是全链路 few-shot 的主样例，8 个工具与全部文档都依赖它。**取舍理由**：另两条路（改核心示例名 / 把副本对齐成美业）都要么动主样例、要么重做导出产物（现有 PNG/SVG 画的是医疗界面），代价与收益不成比例。**改名前先核实了 `qa-export` 的匹配正则是 `^example-[^.]+\.json$`（正向形状，对新名仍匹配），改后实测 `935 PASS / 0 FAIL` 未变。** 顺带记一处**名实不符**：名字 `health` 其实更贴合**医疗**那份，核心示例是「美业」却叫 health——但动主样例性价比低，故只改窄的一侧，并在此如实记下。）

45. **校验器缺文件时必须如实报「缺」，不许自己先崩成堆栈**：`qa-install` 第一版直接 `read("SETUP.md").match(...)`，SETUP.md 一被删，工具就 ENOENT 崩掉——**它连它要抓的那个缺陷（缺文件）都报不出来**，用户看到的只是一段栈，真正的问题反而没被说出口。**判据：校验器的每个输入都要有「不存在」这条路径，且走这条路径时输出的是「问题」，不是异常。** ⚙️（`qa-install.mjs`，变异测试「删掉 SETUP.md」用例守住）

46. **判「代码里有没有这个逻辑」要判形状，别判这个名字出现过**：`includes("figma-developer-mcp")` 会被**头部注释里的同一串字**喂饱——把真正的判定分支删掉，检查照样绿；`includes("::1")` 同样被注释里的 `::1` 喂饱。**判据：断言要落在真实的表达式上（`haystack.includes("x")`、`const X = "::1"` 且 `.listen(PORT, X)`），而不是「这个名字在本文件里出现过」。** 这与 #42「可追溯性判路径能解析、而非前缀看着对」是同一条病换了个地方。 ⚙️（`qa-install.mjs` QA2/QA7，各配变异测试）

47. **降级开关不许「连坐」**：`--no-behavior` 本意是跳过「要起进程/起服务」的检查。但如果文档一致性检查的**真值**恰好来自那次实跑，它就会被一并跳过——**最值钱的检查在降级模式下静默消失**，而汇总里四组「装置缺口」看着还挺诚实。**判据：加降级开关时逐条问「这条检查依赖的是外部环境，还是只是恰好复用了那次实跑的结果」。** ⚙️（`qa-install.mjs`：提示语真值改为轻量恒跑，只跑探针两次）

48. **用例「通过」可能是因为它根本没测到东西，而变异测试是唯一能发现这件事的手段**：`qa-install` 的「bridge 可达但插件未连」用例一直是绿的，但把探针的 `figmaWrite` 改成 `bridge.reachable` 之后**它还是绿的**。根因是装置把 `url` 返回成了含 `/health` 的完整 URL，探针去请求 `/health/health` 得 404，一路退化成「没有 bridge」——这条用例在「连不上」的假象里通过，从来没真的走到那个分支。**判据：变异之后仍然绿的用例，比变异之后变红的用例更值得看。** ⚙️（`qa-install-mutation.mjs` 抓出）

49. **「在启动时打印的值」不等于「被持久化的值」**：bridge 的 `loadOrCreateToken()` 有**四条返回路径，只有最后一条会写 `.vibe/token`**——`--token` 参数与环境变量 `VIBE_TOKEN` 都是**直接返回、不落盘**。于是用 `--token` 启动时，文档承诺的「`.vibe/token` 就是当前 token」**不成立**，照文档取值必然 401。**判据：凡文档声称「A 与 B 是同一个值」，就必须验证**所有**产生 A 的路径都同步了 B，而不只验默认路径。**（`qa-install` QA7 的「token 跨重启持久性」只跑了默认路径，故漏掉此分支；`qa-bridge.mjs` 恰是用 `--token` 起的，两处各自看都对、合起来才暴露。）📏 → ⚙️（2026-09-16 真实环境实测发现；同日补上 QA7 断言与 2 条变异用例后转为已守卫）

50. **行为型断言若起不来进程，绝不能静默降级成「装置缺口」**：给 #49 补断言时，`tokenFileAfterArgToken()` 把 bridge 脚本路径写成了 `<TMP>/skill/bridge/server.js`，而夹具实际只把 bridge 副本放在 `<TMP>/bridge/`——脚本不存在 → 进程起不来 → 返回 `null` → 走 `gap()` 分支。**结果是：断言一条都没跑，而输出里只有一行人畜无害的「装置缺口」，汇总仍是全绿。** 抓出它的是变异测试（注入「`--token` 也落盘」后依然全绿）。**判据：装置缺口可以有，但必须能区分「环境起不来」与「夹具路径本身就错了」——后者是装置自己的缺陷，必须判 FAIL。** 已在 `qa-install` QA7 加一条装置自检断言。 ⚙️（`qa-install.mjs` + 2 条变异用例）

51. **「读到空值」和「读到真实值」在断言里长得一样，只有把值打进断言消息才能分辨**：同一次修复中，修正路径前后的断言**都是绿的**（`res.value !== dictToken` 恒真——读到 `null` 或读到别的 token 都满足）。差别只在断言消息里：修之前打「实际 文件不存在」，修之后打「实际 "fd64bb91…"」——**前者说明这条断言什么都没测**。**判据：凡断言依赖一个外部取值，就把该值打进消息里**，让"恒真"与"真的验过"在输出上可区分。这与 #40「痕迹判定要判形状」、#48「变异后仍绿的用例更值得看」同源。 ⚙️（`qa-install.mjs` QA7 的 `--token` 断言）

52. **校验器只实现了规则的一部分，会把「合法的另一半」判成违规 —— 而这比漏报更早暴露**：`design-system.md` §4.2 明列色值有三个合法来源（Preset / **Brief 显式覆盖** / 白名单派生），但 `qa-l2.mjs` QA2 的色板白名单**只实现了第一条**。于是第一个真的用了「Brief 覆盖背景色」的产物（D2 运行 A 的 #F7F7F9）被判「未知颜色」。**关键区别：这是误报，不是产物错**——判据是去规则原文里找该值有没有合法依据，有则修校验器、无则修产物。**最容易搞反的地方**：看到红灯就改产物去迁就工具，等于让工具的口径覆盖掉已写明的规则。 ⚙️（`qa-l2.mjs` QA2 新增 brief: 分支 + 3 条变异用例）

53. **给校验器补旁路时，「合法放行」与「永久绿灯」只差一句校验**：修 #52 时最省事的写法是「见 `brief:` 前缀就 continue」——但那会让 QA2 变成**一句话就能关掉的检查**（正是 #47「降级开关连坐」的形态：旁路的存在使所有人绕开它）。因此该分支必须同时满足三件事才放行：① `brief:` 后的字段名与该 token 路径匹配（防凭空盖前缀）② 值等于 Brief 里真实声明的值（防改值蒙混）③ 已记入 `sourceMapping.briefOverrides`（防漏审计）。**判据：任何 `continue`/`skip`/`return true` 的分支，都要问「这里能不能被无成本地满足」。** ⚙️（`qa-l2-mutation.mjs` 3 条对应用例；其中第 2 条的断言最初写成「路径不存在」，而实现按字段名校验——**变异测试当场抓出我自己新代码的这条断言与实现错位**，见 #48）

54. **「新加的检查让旧样例变红」时，先怀疑旧样例，别急着豁免**：补完 QA2 的 brief: 分支后，随包的 `example-health.dsspec.json` **基准产物本身红了**——它有 `source: brief:visualSystem.primaryColor`，却从没把这条记进 `sourceMapping.briefOverrides`。**这是样例里真实存在的审计链缺口**（之所以长期没暴露，是因为旧校验器根本不看 brief: 分支，见 #52——两条缺陷互相掩盖）。处理方式：改样例补上那条记录，**不给样例开豁免**。若当时图省事把 `example-health` 加进白名单，这条缺口就会永久固化。 ⚙️（`example-health.dsspec.json` briefOverrides 补第 3 条）

55. **过阈值的量要留下「余量」这个数，否则下一次微调就是静默违规**：D2 运行 A 的 `text.regular #6B7280 on background.page #F7F7F9` 算出 **4.52:1**，过 AA（4.5）只多 0.02。`contrast-audit.mjs` 标了 `⚠边界`，但若只在交付物里写「PASS」，后来者调背景色时不会知道这里已经没有余量。**判据：凡某值距阈值 < 1%，就在产物里显式写明「只多 X，不得再往某方向调」**，把它变成一条约束而不是一个结论。这与 #37「算得出来的数字必须复算」互补——#37 管「数字对不对」，这条管「数字有多勉强」。 📏 → ⚙️（已写入 DS Spec 的 `accessibility.notes`）

56. **承重参数必须有一条能证实它的通道，否则「构建成功」与「参数生效」是两件事**：D2 运行 A 的毛玻璃全部压在一个 `opacity:0.72` 上。`set-effects` 的 `BACKGROUND_BLUR(30)` 能从回读的 `effects` 数组看见，**但填充透明度看不见**——`nodeInfo()` 的 fills 走 `paintToHex()`，该函数只取 `paint.color` 的 RGB，**直接丢掉 `paint.opacity`**。于是 `#FFFFFF@100%` 与 `#FFFFFF@72%` 回读出来都是 `["#ffffff"]`：回读全绿，而真正要验的那个数根本没进观测面。**抓法：在真实 page 底上放「glass 卡 + 不透明对照卡」，导出 PNG 读像素**——实测 `#FDFDFD`（透明合成）vs `#FFFFFF`（不透明基准），2 个通道点即可判定。**判据：写到画布上的每个「承重参数」，都要能说出「哪条观测通道能证伪它」；说不出的，等于没验过。** ⚙️（本轮用 `.vibe/d2-run-a/verify-glass.py` 做像素直方图，属运行期临时装置、未随包发布；`get-node` 侧的回读缺口待补 `paintToHex` 输出 opacity，见待办）

57. **「模糊」需要一个可被模糊的对象，否则结构全绿、画面毫无效果**：D2 运行 A 把毛玻璃做在平板底色 `#F7F7F9` 上——`effects=[BACKGROUND_BLUR(30)]` 回读正确、`fills.opacity=0.72` 回读正确、`qa-critic` 结构项全绿，**但导出图上看不出任何玻璃感**，因为「模糊一块纯色」的数学结果**仍然是那块纯色**。这不是参数没生效，是**参数生效了但没有可观察的效果**。**判据：凡是「改变某个量的处理方式」的效果（模糊/混合/遮罩/裁剪），都要先确认它的输入不是常量——常量输入会让这类效果等价于无操作，且任何结构性回读都发现不了。** 处置：补一个独立背景场景层（`Bg/Scene`，含大尺寸低透明度色斑/色带），再做 A/B 像素对照（卡内 `#E8E8F9` / 空底 `#F4F4F8`）证明差异真实存在。⚙️（`.vibe/d2-run-a/build.mjs` 批次 0；与 #56 是**同一根因的两个面**：#56 管「参数进不了观测面」，本条管「参数进了观测面但没有可观察的后果」）

58. **「超时」是一份残缺的回执，不是一次失败——而超时后的重试可能作用在已生效的画布上**：D2 运行 A 把 10 个 `append-child` 塞进一个 `run`，撞 15s 超时返 `NO_RESULT: picked up "run" but never returned`。按常理这是「没执行完」，于是重试——但重试时那 10 个组件**已经不在原位置了**（`appendChild` 会重挂父级并重算坐标），画布上只剩一个空帧，**两侧都没报错**。这与 #3「超时 ≠ 未执行 ≠ 可重试」是同一族，但 #3 讲的是「大 batch 复制了 3 份」的可见后果，本条补的是**不可见后果**：重挂类 op（`append-child` / `move-node`）是**非幂等**的，重试不会原样重做，而是叠加在中间态上。**判据：超时后的第一动作必须是「回读现状」，不是「重发」；且批量里混入重挂类 op 时，批大小要按「最贵的那个 op」估，不能按 op 条数估。** ⚙️（`.vibe/d2-run-a/build.mjs` 的 `if (ops.length > 30)` 告警；`bridge-ops.md` §3 已同步补写超时语义）

59. **「同一条命令的两个名字」是最难自查的契约歧义：`move-node` 改坐标，`append-child` 改父级**：`bridge-ops.md` §5.3 原只列了 `move-node` 的参数（`id` / `x` / `y`），措辞上很容易被读成「把节点放进某容器」。D2 运行 A 照此把 10 个组件「移」进总览帧，回读**每一步都 `ok:true`**，导出却得到一张 100% `#F7F7F9` 的空白 PNG（6210 bytes）——因为那个帧 `clipsContent:true` 且**子级列表是空的**，所有节点其实还挂在页面根部，被裁掉了。**判据：凡两个 op 名字都像「把 A 放到 B」的（duplicate vs clone、move vs reparent），文档必须显式写出「它动的是哪个属性、不动的是什么」，且必须配一条「导出后看图」的端到端用例——结构回读对这类错误是**全盲**的（每个节点的 x/y/width/height 都合法）。** ⚙️（`bridge-ops.md` §5.3 已补语义区别表；配套「导出成功 ≠ 有内容」的像素直方图检查见 #56）

66. **对 2D 网格做「单轴排序后比相邻」会产出大批假阳性——把节距当成设计间距**：D2 运行 B 的 `layout-audit` 报 21 条，**20 条是假阳性**，而**真缺陷当时一条没报**。假阳性里 17 条同源：`spacing` 检查把子级**按单一轴排序**后比较相邻项（`stack = geoKids.sort((a,b) => a[ax.pos] - b[ax.pos])`），在 2D 网格容器（12×2 设备矩阵、23×18 拓扑网格）里，排序会把**不同行不同列**的元素排成"邻居"。最典型的一条：`"Cell/12" 与 "Cell/13" 的间距 10px`——Cell/12 在 (830,44)、Cell/13 在 (16,98)，**既不同行也不同列**，算出来的 10px 是**行节距**，毫无设计含义（另 4 条是图表时间轴刻度，属等距数据标注）。**判据：凡是要判「间距合规」的检查，都必须先确认两个被比较的元素**在几何上真的同轴相邻**——「排序后相邻」≠「布局上相邻」。** ✅（已收编：加 `crossOverlap > TOL` 前提要求跨轴真有投影交集；另以 `bandByCross` 分带 + `isDataDrivenSpacing` 处理等距刻度。修后 21 → 1 条）

72. **「没查」与「查了没问题」在产物里可能长得一模一样 —— 所以留痕必须做进工具，不能靠人记住传了什么参数**：D2 运行 B 结案时从留存的旧报告读到 `scales: {"minTouch":0, "baseline":null, "font":[14,16,20,22,26]}`，才发上一轮「闸门全绿」是在**三条检查缺席或放宽**的情况下取得的——`minTouch:0` 让触控检查恒不触发（`side < 0`）、`baseline:null` 让基准检查没跑、`font` 含 16 让 16px 的系统性偏差顺利通过。而旧版 `layout-audit` **连 `unchecked` 字段都没有**，所以「关掉检查后报 0」与「检查通过后报 0」**在产物上不可区分**。`touch: 0` 被读成"合格"整整一轮。**判据：① 任何校验器都必须能回答「这轮哪些项没查、为什么」，且答案要落在**产物里**，不是落在人的记忆里；② 校验器的档位参数必须**来自规格原文**（L2 Spec），不能跟着构建脚本里顺手写的一份走；③ 区分两种"没查"——「人主动关掉」要改命令行，「输入不具备」（字段压根没回读出来）要改回读方式或接受无法查，两者成因与修法不同，输出里要分开列。** ✅（已在本仓库落地：`layout-audit.mjs` 增加 `unchecked` / `skipped` / `dataDrivenSpacing` / `inputCoverage` 四个留痕段，控制台单列「未检查」「输入不具备」「已跳过」「已免检」。**其余校验器尚无同类机制，属已知缺口**）

73. **收编一个工具时，必须把它依赖的「前提」一起收编，否则收编的是错报机器**：D2 运行 B 的两个临时装置（重复兄弟检查、兄弟重叠检查）在两个方向上都错过——`spacing` 报 21 条假阳性、真缺陷一条没报。收编时才发现**两个方向的错同源**：判定所依赖的**隐含前提没有写出来**。补上两条前提后，工具立刻从"错报机器"变成"可用的尺子"：① `localSameSpace`（本层子节点须真共享坐标系）——消掉合成页根/多组件帧场景的假阳性；② `bandByCross` + `isDataDrivenSpacing`（**先按交叉轴分带 → 再按名字形态聚类 → 才判等距**）——`spacing` 由 21 条降到 1 条，因为"等距"是**一条带内**的性质，不是**整个兄弟集合**的性质（TrendChart 的横轴时间刻度与纵轴数值刻度名字形态都是空串，混在一起算中位数会把真正等距的那一排连坐）。**判据：① 收编 = 代码 + 前提 + 留痕 + 变异测试，四件一起搬；② 写变异测试时"不误报"那一半比"能抓错"那一半更重要——本轮的 293/213/256 条假阳性全出在这里；③ 变异测试自身的两个陷阱要记住：退出码只由 `high` 决定（medium 报出但不改退出码，对它们断言 `status===1` 是错的），以及**不能拿 `!/关键词/` 当断言**（控制台永远会打印「已启用 … 关键词 …」，否定匹配恒为 false）。** ✅（已收编进 `tools/layout-audit.mjs`，并新增 `tools/layout-audit-mutation.mjs`，**51 PASS / 0 FAIL**）

74. **回写顺序会让「文档里的数」静默漂移——所以验收收尾必须做一次「数字回指产物」的复核**：D2 收尾填实验收记录时逐个数字回指产物，抓到**三处对不上**——`CHANGELOG` 说运行 A「新增隐式知识 **5 条**（#57–#61）」（实为 **9 条 #55–#63**）；说 `lessons.md`「累计 **71** 条」（实为 **73** 条）；守卫覆盖表说重份节点检查「⚠️ 待收编」（实为**已收编**，`layout-audit` 的 `duplicate` 早已落地）。三处**都不是实现错，也都没人撒谎**——成因是**回写顺序**：先按当时的事实写了文档，之后又往里加了内容（补 #62/#63、补 #72/#73、完成收编），**而文档里的那个数没人回头改**。这与 #63（产物里的散文描述会过期）是同一件事的**文档版**，也是 H1 判据「**产物里每个数字要么算得出、要么指得出源**」指向**文档自身**时的用例：文档里的数字**同样会被下游当事实复用**（本次就差点把「71 条」抄进验收结论）。**判据：① 凡文档中出现「N 条 / 累计 N / 第 N 号」这类**可数**表述，收尾时必须回指产物复核一次；② 复核动作要**机械**（`grep -cE "^[0-9]+\."` 数编号、`grep -nE "^7[0-9]\."` 查连续性），不要靠读一遍记得住；③ 若某处数量注定会持续增长，就别写绝对值，改写「见 `lessons.md` 当前最大编号」这类**指得出源**的表述。** 📏（纪律，无自动守卫；已把该动作写进 `references/acceptance-criteria.md` §8.3 的收尾清单）

76. **不存在的 node id 会让插件挂满 10 秒，然后报一个指向错误方向的错误**：1.3 开工做 B2 的实测时顺带发现——对画布上**不存在**的 id 调 `get-node`，插件既不返回 `NODE_NOT_FOUND`，也不快速失败，而是**挂 10 秒**后回 `EXEC_ERROR / Unable to establish connection to Figma after 10 seconds. Please check your internet connection.`（实测 3/3 复现：`999:999` / `1:2` / `7:99999`，均 10.1~11.0s；而真实存在的 `7:328` 54ms 就回）。这**不是**我们的网络问题——`figma-plugin/code.js` 的 `getNode` 明写 `if (!node) throw fail(..., "NODE_NOT_FOUND")`，说明代码本来预期 `figma.getNodeByIdAsync()` 对缺失 id 返回 `null`；但在 `documentAccess: "dynamic-page"` 下它对**不存在的 id** 会去尝试加载对应页面，加载失败后由 Figma 宿主抛出这句"网络"错误。**两个后果**：① **诊断陷阱** —— 报错文案把「id 不存在」说成「检查网络连接」，会把人引向完全无关的方向；② `precheck --live` 设计里「核出不存在」的专门路径（判 `NODE_NOT_FOUND` → 打印「画布上不存在这个节点」）**在本环境永不触发**，所有缺失 id 都落进「意外响应」并判 FAIL。**好在 FAIL 的方向是安全的**（不会把没核成说成通过，见 E 组变异用例），但**计数会失真**：`核出不存在` 恒为 0、`未核对` 偏大。**判据：当宿主 API 对"查不到"这一情形返回的是**别的类别的错误**时，不要在工具层用关键词去猜（那会把真·连接故障也吞掉）；如实按「意外响应」报 FAIL 是本环境唯一不撒谎的选择，并在文档里写明这条边界。** ⚠️（根因修复需改 `figma-plugin/code.js`，**属冻结区**，不得在构建期动——与 #61 同类，记入 1.3 候选向冻结区提需求；本轮**未改**任何冻结文件）

85. **判据里写的外部凭证，先问它是「产物性质」还是「某个拓扑的前提」—— 后者换了拓扑就从判据变成噪音，而「换判据」与「放宽判据」的差别必须用实测数字证明**：1.3 立项第 0 项裁掉 `qa-export` QA3 的「`live-build` 必须有 `figmaFileKey`」。这条断言**没有逻辑错**（有 fileKey 确实更可追溯），它的真身是**上游 REST API 拓扑的前提**：那里「回读」= `GET /files/{key}/nodes?ids=…`，**没 key 就真读不回来**。而本管线的回读通道是 **Bridge 直连插件**，`get-node` 凭 `nodeId` 单键即可，且插件**没有任何 op 返回 `figma.fileKey`**（冻结区缺口）⇒ 在本拓扑下它不是判据，是**噪音**：**两次独立实跑**（运行 A / 运行 B）都撞上同一条，每次收口都得额外解释「FAIL 的是环境凭证、不是产物质量」。
    **动的是判据，不是尺度 —— 三件事各做对**：
    - **① 换成「必须交代」，不是「删掉」**：改为「拿不到就**如实标 `null`** 并在 `_meta.note` 说明缺口」。这正是 #72 的判据在**判据层**的形态 —— 「没查要有专门的输出形态」，那么「拿不到也要有专门的输出形态」。
    - **② 裁剪时**逐格**检查边界输入**：第一版把分支写成 `if (!fk)`，于是**空串**被归进「如实标 null」——`figmaFileKey: ""` 只要补一句 note 就过关了。而旧判据用 `!!` **恰好**把空串拦下过。⇒ 必须写成 `fk == null`（只认 `null` / 缺字段），并补一条「**已声明就必须非空**」。**同一个字段有四种「没有」：`null` / 缺字段 / 空串 / 全空白 —— 它们不是一回事，裁剪时必须逐个过一遍。**
